Wizja

Sharbo przechowuje wewnętrzne memy, cytaty i sytuacje, które rozumie tylko zamknięta grupa ludzi. Grupa może mieć dwie osoby (jak rozmowa 1:1) albo całą ekipę. Każdy wpis można przypisać członkom grupy i ma datę, godzinę oraz miejsce, żeby po latach dało się wrócić do kontekstu.

Backend w C# obsługuje dwa klienty: aplikację mobilną (robi ją inna osoba) i prosty frontend webowy w React. Kontraktem między nimi jest specyfikacja OpenAPI.

Słowniczek

Grupa
Zamknięta przestrzeń kilku osób. Tylko jej członkowie widzą wpisy.
Uczestnik
Użytkownik w konkretnej grupie, z rolą: Admin, Moderator albo Uczestnik.
Wpis
Mem (obrazek z opcjonalnym tekstem), cytat albo sytuacja (opis zdarzenia).
Przypisanie
Wskazanie, kogo dotyczy wpis: kto to powiedział albo kto brał udział.
Moment i miejsce
Kiedy to się wydarzyło (nie kiedy dodano wpis) oraz współrzędne z nazwą miejsca.
Zaproszenie
Kod albo link z datą ważności, przez który ktoś dołącza do grupy.

Ustalony stack

Decyzje na najbliższe fazy. Co nie jest tu wpisane, zostaje otwarte.

ObszarWybórDlaczego
Runtime.NET 10 (LTS), C# 14Wsparcie do listopada 2028. Przy okazji paczki 9.0.0-rc zamieniamy na stabilne.
LokalnieDocker Compose: API, PostgreSQL, AzuriteRozszerzamy istniejące docker-compose.yml i Dockerfile. Azurite emuluje Azure Blob na laptopie.
BazaPostgreSQL, EF Core 10Rezygnujemy z SQLite: jeden provider i jeden zestaw migracji. Lokalizacja jako szerokość, długość i nazwa miejsca.
AuthFirebase AuthenticationKlient loguje się przez SDK Firebase (Google, Apple, e-mail), a API tylko weryfikuje ID token. Własne JWT, refresh tokeny i kolumna z hasłem znikają.
PlikiAzure Blob Storage, upload przez APIAPI sprawdza typ po zawartości pliku i limit rozmiaru, nadaje własną nazwę, usuwa EXIF (z lokalizacją GPS) i zapisuje WebP (ImageSharp). Odczyt bezpośrednio z prywatnego kontenera przez krótko ważny adres SAS. Okazja do nauki Azure.
Kontrakt APIOpenAPI z .NET + ScalarSpec openapi.json w repo jest umową z osobą od mobilki. Scalar zastępuje Swaggera jako podgląd.
BłędyProblemDetails + FluentValidationKażdy błąd ma ten sam kształt JSON, z którego korzystają oba klienty.
CI/CDGitHub ActionsJuż działa: build, testy z pokryciem i obraz Dockera w GHCR przy tagu v*. Krok deploy dojdzie razem z wyborem hostingu.
TestyxUnit v3, Testcontainers, AwesomeAssertionsTesty endpointów na prawdziwym Postgresie w kontenerze. FluentAssertions 8 jest płatne komercyjnie, a AwesomeAssertions to darmowy fork z tym samym API.

Architektura

Trzy usługi zewnętrzne, jedno API. Zapis pliku przechodzi przez API, które go sprawdza i czyści. Odczyt idzie bezpośrednio z Blob Storage, żeby API nie przepuszczało każdego wyświetlenia obrazka.

Model danych MVP

Docelowy schemat bazy dla MVP, z typami kolumn PostgreSQL. Punkt odniesienia: porównaj go z kodem, żeby zobaczyć, czego jeszcze brakuje.

Makiety

Szkic przepływu, nie finalny wygląd aplikacji. Klikaj w makiecie albo w liście ekranów i przełączaj między telefonem a webem. Frontend webowy jest jeszcze TBD, więc wersja web pokazuje tylko proponowany układ.

Roadmapa

Każda faza to osobne issue i PR. Testy dopisujemy w trakcie każdej fazy, nie na końcu.

  1. Krok 1

    Dokument i makiety

    Gotowe
    • Ten dokument: stack, architektura, model danych, makiety.
    • Model z fazy 3 do potwierdzenia na makietach.
  2. Faza 1

    Fundament

    Zaplanowane
    • .NET 10 i stabilne paczki w global.json, projektach, Dockerfile i CI.
    • Usunięcie SQLite; docker-compose.yml z Postgresem i Azurite; sekrety przez user-secrets i zmienne środowiskowe.
    • Nowa migracja Initial od zera.
  3. Faza 2

    Auth i uprawnienia

    Zaplanowane
    • Weryfikacja Firebase ID tokenu; bieżący użytkownik z tokenu zamiast wpisanego na sztywno ID w serwisach.
    • Dostęp do danych grupy tylko dla jej członków, z uwzględnieniem ról.
    • Profil użytkownika zakładany po pierwszym logowaniu; koniec publicznej listy użytkowników; usunięcie kolumny z hasłem.
  4. Faza 3

    Model domeny

    Zaplanowane
    • Gotowe w kodzie: memy, cytaty i sytuacje w jednej tabeli Entries (TPH); dyskryminator Type to nazwa klasy, bez osobnego enuma.
    • Wpis: grupa, moment zdarzenia, miejsce, przypisane osoby.
    • Zaproszenia kodem lub linkiem z datą ważności.
    • Do rozważenia: role jako enum zamiast tabeli Roles.
  5. Faza 4

    Jakość API

    Zaplanowane
    • Wszystkie błędy jako ProblemDetails; poprawne odpowiedzi 201 Created.
    • OpenAPI ze Scalarem i openapi.json w repo dla mobilki.
  6. Faza 5

    Pliki na Azure Blob

    Zaplanowane
    • Upload przez API (multipart): sprawdzenie typu po zawartości, limit rozmiaru, własna nazwa blobu, usunięcie EXIF, konwersja do WebP.
    • Odczyt z prywatnego kontenera przez krótko ważny adres SAS tylko do odczytu.
    • Lokalnie Azurite, w chmurze konto Storage założone w Azure.
